一、系统是怎么工作的

一台 NAS（飞牛 fnnas）在家里的局域网里跑着代理程序（mihomo），它负责"分流"——国内网站直接走家里宽带，国外网站走代理节点。其他设备用不同方式把流量交给它。

流量类型 处理方式 表现
国内 直连 显示本地宽带 IP（运营商分配），不经过代理
国外 走代理 自动选最快节点，显示海外 IP
分流方式 自动 靠域名规则 + fake-ip（198.18.x.x 保留段），设备无需手动判断

核心逻辑： 国外域名解析后返回假地址 198.18.x.x（RFC 保留段，非真实地址），流量被引回 NAS 走代理；国内域名返回真实 IP，直接出网。所以国内网站始终保持本地 IP。

涉及的两台机器

机器 地址 用途
NAS（fnnas，ARM Debian） <NAS局域网IP>（局域网）
<NASTailscaleIP>（Tailscale）		 跑代理服务，整套管家的核心
KH0095（Windows 电脑） <KH0095IP> 另一个网段，通过 Tailscale 地址连代理

三、各设备怎么用

① 局域网手机 / 电脑 —— 不用设置（零配置）

前提（已配置好，一般不用动）：路由器 DHCP 的 DNS 指向 <NAS局域网IP>，且路由器有一条静态路由把 198.18.0.0/16 引向 <NAS局域网IP>。

  • 连上同一个 Wi-Fi 就能用，不用填代理、不用装软件。
  • 换网络后若没生效，重连一次 Wi-Fi（刷新 DNS）即可。
  • 验证：浏览器开 https://www.google.com 能打开；开 https://myip.ipip.net 显示本地宽带 IP（说明国内直连没被代理）。

优点： 网关仍指向路由器 <网关IP>，所以 NAS 关机只影响国外网站，国内网站照常上。

② KH0095 电脑 —— 双击桌面脚本

这台机器和 NAS 不同网段，连的是 Tailscale 地址。桌面有两个启动器，效果相同：

文件 特点 推荐
edge_proxy.vbs 双击无黑框，Edge 窗口正常打开 ✅ 推荐
edge_proxy.bat 双击会弹一个黑色命令行框 备用

操作步骤：

  1. 双击桌面的 edge_proxy.vbs。
  2. 脚本会先自动关掉所有旧 Edge 进程（含后台常驻的），再启动带代理的新 Edge。
  3. 关掉 Edge 窗口，代理自动失效，不留系统级设置。

⚠️ 务必注意： 只有脚本启动的 Edge 才带代理。直接点 Edge 图标、或命令行敲 msedge 打开，都是不翻的。这是设计如此，不是故障。

脚本内的代理地址已写成 <NASTailscaleIP>:7890，部署时请把该占位符替换成实际 Tailscale IP。

③ 其他想手动配置的设备

在设备的网络/Wi-Fi 设置里填代理（自动分流仍由 NAS 负责，国内照常直连）：

  • HTTP 代理：<NAS局域网IP>:7890（同网段）或 <NASTailscaleIP>:7890（Tailscale）
  • SOCKS5：<NAS局域网IP>:7891 或 <NASTailscaleIP>:7891

④ NAS 本机浏览器

通过飞牛远程桌面打开的 Chromium，已在服务启动参数里内置代理，打开即自动带代理，不用做任何设置。

四、控制面板使用

打开 http://<NAS局域网IP>:9090/ui/（局域网）或 http://<NASTailscaleIP>:9090/ui/，首次提示时填密钥 <面板密钥>。

「代理」页的四个策略组

策略组 类型 作用
自动选择 url-test 每 5 分钟测速，自动挑延迟最低的节点（日常走的就是它）
故障转移 fallback 主节点挂了自动切下一个，每 3 分钟检测
手动切换 select 想固定某个节点时手动选
GLOBAL select 全局组，一般保持 DIRECT 即可，不影响实际分流

卡片上的数字怎么看

  • [7/269]：可用节点数 / 总节点数，随测速动态变化。
  • 卡片上的 84 / 107：当前节点延迟（毫秒），越小越快。
  • 0 B/s：当前实时流量，有下载时会跳动。
  • 右上角图标：搜索 / 测速 / 展开 / 刷新延迟。

节点从日本/新加坡等来回切换是自动测速的正常行为，说明"选最快"在工作。

五、自动刷新频率

项目 间隔 说明
订阅节点更新 1 小时 自动从订阅地址拉最新节点
自动选择测速 5 分钟 挑最快节点，失效节点最多 5 分钟内被换掉
故障转移检测 3 分钟 检测主节点是否存活
GeoIP / GeoSite 规则库 24 小时 更新国内外分流规则

全部自动运行，不需要人工干预。

六、怎么判断代理是否正常

最简单：控制面板

打开面板「代理」页，看节点是否有延迟数字、「仪表盘」是否有实时连接。有连接就说明在用。

登到 NAS 上一行命令测

curl -x http://127.0.0.1:7890 -o /dev/null -w '%{http_code}\n' https://www.google.com

127.0.0.1 是本机回环地址（通用技术常量，非设备真实地址），故保留不脱敏。

返回 200 正常；000 或超时说明代理断了。

完整自检清单（排查时用）

检查项 正常标准
两个服务 mihomo 和 mihomo-tproxy 都 active
端口监听 53 / 7890 / 7891 / 7893 / 9090 都在听
节点数量 约 269 个，updatedAt 是近期时间
国外网站 经代理 Google / YouTube 返回 200
国内网站 百度直连返回 200，显示本地 IP
DNS 分流 Google → 198.18.x.x，百度 → 真实 IP
默认网关 <网关IP>（绝不能是 <NAS局域网IP> 自己）
转发规则 iptables mangle 里跳转规则正好 1 条，不重复

七、常见问题排查

现象 原因 解决
KH0095 上 Edge 打不开 Google 没走脚本启动，Edge 命令行没带 --proxy-server；或旧 Edge 后台常驻导致参数被忽略 双击 edge_proxy.vbs 重新启动（它会先关干净旧进程）
面板显示"未信任 / 未授权" 没填密钥 连接框里填 <面板密钥>
所有网站都打不开、DNS 全超时 NAS 默认网关被改成了 <NAS局域网IP>（它自己），流量在内部打转 改回 <网关IP>：ip route replace default via <网关IP> dev eth0
局域网设备国外网站打不开，国内正常 设备的 DNS 没指向 NAS，或路由器静态路由丢失 确认 DHCP 的 DNS=<NAS局域网IP>，静态路由 198.18.0.0/16→<NAS局域网IP> 还在
在 NAS 本机浏览器开 Google 打不开 本机流量走 OUTPUT 链，不经过透明代理（属正常现象） 本机要用远程桌面的 Chromium（已内置代理），或显式设 127.0.0.1:7890
之前能用的外网路由器链接突然打不开 路由器的外网端口映射失效 / 运营商不给公网端口（与代理无关） 在家里用 http://<网关IP> 进路由器，检查端口映射规则

八、注意事项

  • NAS 不能随便改网关： 它的网关必须是 <网关IP>，绝不能指向自己 <NAS局域网IP>，否则全屋断网。
  • 代理只跟脚本走： KH0095 上只有双击 edge_proxy.vbs 启动的 Edge 带代理，点图标不带。
  • Edge 启动增强： 关窗口后仍有后台进程常驻（正常现象），所以脚本内置了强制清理再启动。
  • 透明代理服务： mihomo-tproxy 万一显示 failed，登 NAS 执行 systemctl reset-failed mihomo-tproxy && systemctl start mihomo-tproxy 即可恢复。
  • 国内 IP 不变： 国内网站始终显示本地宽带 IP，这是分流设计，不是代理失效。
  • 密码备忘： 请自行妥善保管 <面板密钥> 及各设备登录密码；本文不记录任何真实凭据，修改后旧密钥立即失效。

一句话总结： 国内网站走本地宽带、国外网站自动走代理；局域网设备零配置，KH0095 双击脚本，控制面板看状态——出问题先看第六节自检清单。
